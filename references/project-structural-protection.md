# 项目正文结构保护协议（受控生产模式）

适用范围：文学与证据方法可用于任何任务；文中“项目”“受控生产”“协调者”“正文负责人”和独立报告要求仅指显式启用的 CONTROLLED_PRODUCTION。普通单 Agent 模式保持 SELF_AUDIT_ONLY 与零命中放行，不伪造独立报告或签名。模式与完整执行顺序见 [production-workflow.md](production-workflow.md)。

本参考适用于显式启用 CONTROLLED_PRODUCTION 的任务。它把一次“新稿 AIGC 指标升高、但提交分段和解析条件不可比”的回退经验转成可审计的生产门，不是检测器规避指南，也不是项目事实源。

## 1. 候选进入顺序

对每个新建或实质修订的完整无标题正文候选，按以下顺序留证：

1. 机械装配闭合，取得候选正文 SHA-256。
2. 用同版冻结章纲执行一次性 `OUTLINE_EXPRESSION_COVERAGE`；入口、必须场景、人物行动与选择后果、生活／环境功能、信息顺序、章末接口和核心未知边界（人物视角信息隔离、主线科研节奏、思想暗线叙事控制）均须有位置证据。其他兼容新增细节只要求候选事实登记，不把未登记本身当作正文缺陷。
3. 通过 `references/production-workflow.md` 的 受控生产 覆盖与 用户明确的长度要求 门。
4. 生成完整正文的 UTF-8 分段语义审计；受控生产 新候选要求 `SEGMENT_BOUNDARY_SEMANTIC_CHECK_V2/result=PASS`，不得带 review flag。
5. 报告B逐场完成对白—动作握手；有对白逐轮记录议程、知识边界、相邻动作和后状态，无对白登记理由。
6. 做一次盲态全章冷读，形成 `PRIMARY_FINDING`、范围、保护声线和结构基线对照。
7. 只有内部文学门闭合后，才读检测报告并决定整改范围；双目标模式下同时登记 `AIGC_COMPATIBILITY_TARGET` 与证据等级，并把连续加权层与阈值分桶层分开记录。项目每个机械命中必须逐项处置：默认修复到消失；任何保留必须取得正文负责人主智能体＋三个独立子智能体四份报告与协调者签名裁决，科研项额外附领域审查者报告。章纲层科研豁免不能越过机械命中；普通`KEEP / REVIEW_FLAG`不能成为最终状态。

## 2. 结构回退检查

候选与基线至少比较：场景／段落数量、入口到课或到场链、群像或生活压力、人物打断、行动阻力、知识变化、未决残留、章末出口，以及作者／轮次接缝。字符数减少本身不是缺陷；若字符／段落减少同时使上述功能消失，而“观察—解释—再确认—局部收束”同质回合增加，登记 `COMPRESSION_INDUCED_EXPOSITIONAL_MONOCULTURE`。

同一解释程序跨三个以上场景、人物或物件复现，登记 `DISTRIBUTED_VOICE`。它不是局部红句，不能靠删一处尾巴、替换几个同义词或增添随机生活动作解决。若声线问题与多个作者接缝相连，登记 `NEXT_AUTHOR_HANDOFF`，保持正文不变，直到合法作者门实际开启。

## 3. 处置矩阵

| 观察 | 允许状态 | 禁止动作 |
| --- | --- | --- |
| 单一连续区域，功能未丢失 | `BOUNDED_REGION_REAUTHOR`（需已有授权；可绑定双目标检测机制） | 多处散改、无边界检测追分 |
| 多场景同质声线 | `DISTRIBUTED_VOICE / NEXT_AUTHOR_HANDOFF` | 局部润色冒充解决 |
| 压缩后说明骨架保留、生活纹理消失 | `PRIMARY_FINDING_UNRESOLVED` | 继续扩写补长度、灌入新事件 |
| 只有检测报告分数变化且文学原因未闭合 | `AIGC_COMPATIBILITY_TARGETED_WITH_GUARDS / REVIEW_FLAG` | 依据颜色或分数逐句清洗 |
| 确定世界硬伤或正文无法解释的事实冲突 | 交世界观／协调者事实门 | 由自然度 Skill 自行判定事实 |

样式与声线问题不等于正文事实拒收。经用户授权，句式成簇问题可以按 `SYNTAX_BOUNDED_REPHRASE` 在单一连续窗口内调整；它仍必须通过语义等价、结构零增量、文学回归和 AIGC 双目标验收。否则只能阻断当前声称“已改善”或下游送审，候选仍保留为历史证据。

上表中的`REVIEW_FLAG`只允许作为整改过程状态。进入双审前必须按`project-finding-disposition.md`完成初始／最终审计与逐项台账验证；权限不足时进入合法作者门，不能把未处理提示当作已闭合。

## 4. 最小记录字段

`AI_TRACE_AUDIT` 至少绑定：源稿与基线路径／SHA、盲态冷读时间、`PRIMARY_FINDING`、`FINDING_SCOPE`、`VOICE_PROTECTION`、结构对照摘要、`OBJECTIVE_MODE`、`AIGC_COMPATIBILITY_TARGET`、检测证据等级、处置动作、未决项和下一依赖。报告不得写普适“通过检测器”“不可检测”或保证性规避承诺。

## 5. 选定回归对象 回归样本与用户放行

选定回归对象 原活动正文与用户判定不合格的新候选共同构成项目 Skill 的固定回归样本。新候选不得以“脚本命中减少”或“检测分数更低”单独通过；必须证明入口、场景链、生活／群像压力、人物声音和章末出口没有相对基线退化，同时达到已登记的 AIGC 适配目标，且 `PRIMARY_FINDING_UNRESOLVED` 不存在。

用户要求外部 AIGC 报告作为最终放行条件时，报告必须在正文完全冻结后生成，并尽量保持同一检测器、提交格式、可见文本归一化、分段方式和时间邻近性。项目记录报告路径／SHA、可比性、机制目标和用户裁决；可把机制类别写入受控返工卡，但不把私有逐句词表转换为自动循环。最终放行条件固定为 `LITERARY_REGRESSION=PASS AND USER_DETECTOR_ACCEPTANCE=PASS`；缺一项即保持 `CANDIDATE_ONLY`。
