# 外部小说拆解 Skill：方法层参考

来源：用户提供的 `CloudLiu1008/distill-novels` `SKILL.md`（上游地址：<https://github.com/CloudLiu1008/distill-novels>）。

本文件只记录可迁移的方法，不是任何使用者的事实源、章纲、人物设定、审查结论或授权文件。它不能覆盖正文门、哈希证据、作者边界、专业审查或终止状态。

## 可吸收的工作框架

- 先把任务路由成 `SOURCES / DIMENSIONS / MODE / DEPTH / DESTINATION`。来源可是一部或多部作品；多部作品除非用户明确说明属于同一连续体，否则分开建档。
- 先做来源清单，记录稳定 `source_id`、文件格式、提取警告和章节边界；大语料按章节切片，不反复把整部作品灌入上下文。
- 每个来源先独立提取，再做跨来源综合。综合时分开共同技法、对照实现、来源特征和可迁移原则。
- 每项判断带章节、标题或行区间等证据定位，并明确区分文本事实、强推断和猜测。
- 把风格描述转成可操作观察维度，例如句长变化、句法、意象密度、叙事距离、对白比例、段落节奏和场景转接；不要复制原文或建立长引文库。
- 抽取时保留“欲望→阻力→选择→后果→状态变化”的因果链；设计、改稿和一致性检查分别作为后续动作，不混为一轮抽取。

## 与通用能力的对应

- `natural-prose-audit` 使用上述维度做文学冷读和声线保护，但不根据检测分数直接改稿；任何正文改动仍须有检测器无关的文学理由并命中已登记主病灶。
- `scene-event-weaver` 负责把抽象技法落成任务专属 `scene-profile` 和事件库。外部种子只能启发机制，不能直接成为用户作品的事实或剧情结果。
- 卷级规划可参考“开篇吸引力梯度”和“目标→阻力→选择→代价→残留”的场景节拍；5—8章局部剧情结算窗仍是软检查窗口，不是高潮配额。

## 明确不迁移的做法

- 不承诺绕过朱雀或任何 AIGC 检测，不声称“保证通过”或“无 AI 特征”。
- 不采用固定删副词、删标点、固定句长、固定段长、感官／笑点／高潮配额等机械清洗。
- 不把外部提示词、输出模板或来源作品的专名、人物、情节、独特措辞直接装入正文生产链。
- 不把来源推断默认为作品事实；用户稿件、活动事件库、人物弧线和外部锚点必须继续分层保存。
- 不因方法层建议自动覆盖已确认内容；触及事实、结构或授权边界时回到相应核验步骤。

## 使用时的最小交付

方法吸收或来源拆解应至少保留来源清单、选择的维度、证据定位、推断等级、采用／拒绝项和剩余警告。若来源提取不完整、章节边界不确定或元数据不明，必须在报告中显式标注。
